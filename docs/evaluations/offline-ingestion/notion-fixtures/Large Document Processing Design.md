# Oversized processing design

The Atlas document-processing pipeline converts authorized workspace pages into searchable evidence while preserving enough source information for citations, deletion, and later re-indexing. The Intake Coordinator begins a run only after it receives a connection identifier, a stable Notion page identifier, and the identity of the authorized workspace connection. It does not accept arbitrary page text from callers because the ingestion service must fetch content through the configured read-only connection. The coordinator first requests the page metadata and block tree, records the source edit time as a change signal, and traverses supported child blocks in their original order. The Normalization Worker converts supported headings, paragraphs, lists, code, quotes, links, page references, columns, and simple tables into a canonical document representation. Unsupported media, embeds, application blocks, and advanced database views are recorded by type and skipped without rejecting the rest of the page. The canonical representation preserves the page title, heading hierarchy, block identifiers, table-header declaration, row boundaries, displayed link text, and link destination. It removes presentation details that cannot affect retrieval, such as colors and decorative styling, because visual fidelity is outside the indexed-document contract. Once normalization finishes, the Change Detector calculates a content hash over every supported element that can affect chunk content, embedding input, or provenance. A matching hash means the indexed evidence has not changed, even when non-content metadata such as the source edit time has moved forward. A different hash creates a new document revision and sends the normalized document to the Chunk Planner. The planner groups small neighboring blocks under their closest heading so that related ideas remain together. It keeps table rows complete when possible and repeats a declared header row when a table must be divided across chunks. It never guesses that the first row is a header when Notion has not declared one. The complete embedding input contains the retrieval instruction required by the selected model, the page title, the heading path, and the evidence text. Token counting therefore uses the selected embedding model's tokenizer instead of character length or an approximate word count. Before adding source text, the planner reserves part of the model limit for instructions and structural context. When one paragraph exceeds the remaining budget, the planner tries sentence boundaries first, then word boundaries, and finally tokenizer boundaries for an indivisible span. Every resulting fragment retains the identifier of the original Notion block, receives an ordered fragment index, and may repeat a small bounded amount of source text from the previous fragment. Repeated page titles and headings are stored in the embedding input for retrieval context but are not presented as quoted evidence. Silent truncation is forbidden because missing text would make retrieval incomplete without producing an ingestion error. The Embedding Worker receives deterministic chunks and produces one dense vector for each complete embedding input. It applies the model's documented query or passage instruction and vector-normalization requirements. A bounded batch size prevents a large page from exhausting GPU memory, while retry handling isolates temporary model-runtime failures from invalid input. An input that still exceeds the model limit is rejected as a chunking defect rather than truncated by the tokenizer. Successful vectors are staged with their chunk identifiers, document identifier, revision identifier, source page URL, connection identifier, heading path, and contributing block identifiers. The Index Publisher makes a prepared revision searchable only after normalization, chunking, and embedding have completed successfully. If any preparation step fails, the previous indexed revision remains available. The first implementation may replace the old vectors through several storage operations and therefore does not promise atomic revision switching, but deterministic chunk identifiers make repeated upserts safe. Authorization is enforced before retrieval by filtering on connection identifiers available to the authenticated user. A page URL or block identifier is citation information, not an access token, so citation resolution repeats the same authorization check. When a page is confirmed deleted or access to its configured connection is revoked, cleanup removes its document record and every vector carrying the document identifier. A timeout, rate limit, or temporary Notion error never proves deletion and must not trigger destructive cleanup. The ingestion queue uses at-least-once delivery because losing a page update is worse than processing the same revision twice. Workers acknowledge a message only after its result has been published or classified as a permanent failure. Temporary Notion errors use exponential backoff with jitter, model-service overload reduces batch size before retrying, and repeated permanent failures enter a dead-letter queue for investigation. Each run records its start time, finish time, source page, outcome, block count, unsupported block types, chunk count, fragment count, embedding model, retry count, and failure category. These diagnostics support operations but are not copied into every searchable vector unless filtering or citation requires them. The service tracks indexing throughput, query-independent embedding latency, peak worker memory, and the number of inputs approaching the token ceiling. Alerts focus on sustained failures, growing queue age, authorization-filter errors, and unexpected truncation attempts. Deployment starts with a single worker process and a small concurrency limit so evaluation results are easy to reproduce. Capacity can later grow by adding stateless workers that share the queue and storage systems. The design favors complete and traceable evidence over maximum ingestion speed: a document becomes searchable slightly later if necessary, but no supported text should disappear silently and no citation should bypass the user's authorized connection.

# Processing component matrix

| Component | Responsibility | Owner | Failure action |
| --- | --- | --- | --- |
| Intake Coordinator | Starts an authorized page-ingestion run | Search Platform | Retry temporary source failures |
| Notion Client | Fetches page metadata and blocks | Integrations | Apply rate-limit backoff |
| Block Traverser | Visits child blocks in source order | Search Platform | Record traversal failure |
| Normalization Worker | Builds the canonical document | Search Platform | Reject malformed supported content |
| Link Resolver | Preserves displayed text and destinations | Integrations | Keep text and record unresolved target |
| Table Normalizer | Preserves header declarations and rows | Search Platform | Reject inconsistent row width |
| Change Detector | Compares canonical content hashes | Search Platform | Recompute after normalization |
| Chunk Planner | Creates structure-aware chunks | Relevance | Reject impossible token budgets |
| Token Counter | Counts complete model inputs | ML Platform | Fail instead of truncating |
| Fragment Splitter | Splits oversized source blocks | Relevance | Use deterministic fallback boundaries |
| Embedding Worker | Generates dense vectors | ML Platform | Retry bounded transient failures |
| Batch Controller | Limits inference batch memory | ML Platform | Reduce batch size |
| Revision Stager | Holds a prepared document revision | Search Platform | Retain the previous revision |
| Index Publisher | Publishes searchable vectors | Search Platform | Retry idempotent upserts |
| Authorization Filter | Restricts retrieval by connection | Identity Platform | Deny retrieval on uncertainty |
| Citation Resolver | Resolves pages and contributing blocks | Search Platform | Repeat authorization check |
| Cleanup Worker | Removes confirmed deleted documents | Search Platform | Never delete on transient errors |
| Retry Scheduler | Applies delayed retry policies | Platform Runtime | Add jitter and retry limits |
| Dead-letter Handler | Retains permanent ingestion failures | Platform Runtime | Alert for investigation |
| Metrics Reporter | Publishes ingestion measurements | Observability | Buffer temporary export failures |
