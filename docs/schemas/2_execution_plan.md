# Execution Plan Contract

### 1. Execution Plan

```json
{
  "executionSteps": [
    {
      "stepId": "string",
      "subQueryId": "string",
      "action": "string",
      "capability": "string",
      "arguments": {
        "query": "string"
      },
      "dependsOn": []
    }
  ]
}
```

- `stepId`: Generated by the server/application.
- `subQueryId`: References the corresponding sub-query from the Query Decomposition stage.
- `action`: Describes the operation the LLM planner intends to perform to address the sub-query.
- `capability`: Identifies the registered capability selected by the planner.
- `arguments`: Contains the structured parameters required by the selected capability. These arguments are passed to the tool during execution and must conform to the capability's supported argument schema.
- `dependsOn`: Contains the IDs of execution steps that must complete successfully before this step can execute.

## 2. Execution Plan Responsibilities

- The LLM planner generates the action, capability, arguments, and dependencies.
- The application validates the generated plan before execution.
- The application generates execution step IDs.
- The execution engine passes the structured arguments to the selected tool.
- The `action` is descriptive and is not automatically used as a tool argument.
