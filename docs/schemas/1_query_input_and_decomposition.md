# Query Input and Decomposition Contract

### 1. Identity

The request is associated with an authenticated user identity.
The authentication mechanism is outside the query contract.

### 2. User Request

The user sends a `POST /query` request with the following body:

```json
{
  "conversationId": "string",
  "query": "string"
}
```

* `conversationId` is optional and identifies the conversation. It is created by the server when a new conversation is started.
* `query` contains the user's current request.
* `queryId` is created by the server for every query and identifies that query within the conversation. It is therefore not part of the client request body.

### 3. Query Decomposition

Once the request reaches the API, it enters the agentic flow.

The Query Decomposition stage breaks the user's query into smaller sub-queries.

```json
{
  "subQueries": [
    {
      "subQueryId": "string",
      "subQuery": "string"
    }
  ]
}
```

* `subQueryId` identifies the decomposed sub-query and is generated by the server/application, not by the LLM.
* `subQuery` represents an individual question or task derived from the user's original query.
